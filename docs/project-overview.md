# Nuada Airgetlám × 뉴로워치 — 프로젝트 방향 (2026-11 개편)

> 이 문서는 프로젝트 방향이 바뀐 내용을 설명합니다.
> 처음 계획(README의 1~3단계 로드맵)과 무엇이 달라졌는지, 지금 무엇을 만들고 있는지를 정리했습니다.

---

## 1. 한 줄 요약

> 뇌파로 읽은 의도를 **관제 시스템(관문)**이 먼저 검사하고, 통과한 명령만 **화면 속 로봇팔 1개**로 보낸다.
> 뇌파 측정 오류가 생기면 **RAG**가 오류 종류와 점검 방법을 근거와 함께 안내한다.

이 프로젝트는 **실사용을 고려해 설계한 연구용 프로토타입**입니다.
공개 뇌파 데이터와 화면 속 2D 로봇팔을 사용하며, 실제 환자·실물 로봇·의료기기 안전성을 검증한 시스템이 아닙니다.

---

## 2. 무엇이 바뀌었나

| | 처음 계획 | 바뀐 방향 |
|---|---|---|
| 중심 | 환자가 뇌파로 로봇팔을 조종 | 뇌파와 로봇팔 **사이의 관제탑** |
| 합쳐진 아이디어 | — | 뉴로워치(뇌파 장비 관제 + RAG 매뉴얼) |
| AI의 역할 | LLM이 행동 후보 제안 | RAG가 **오류 원인과 점검 방법만 안내** (제어 명령은 실행하지 않음) |
| 첫 발표 범위 | 1단계 Spring 기본기 | 판별기 → 관제 → 2D 팔 → 차단 기록 → RAG의 **통합 흐름** |
| 착수 순서 | Spring 회원·연결부터 | **EEG 판별기부터** |

기존에 만든 Spring 코드(회원·환자·보호자 연결, 연구자 배정, 연구 동의 철회)는 그대로 유지하며 관문의 규칙에 활용합니다.

---

## 3. 왜 관제탑이 필요한가

1. **뇌파는 잡음이 많다** — 전극 접촉 불량, 전원 잡음, 근육 움직임
2. **판별은 틀릴 수 있다** — 확신이 낮은 명령을 그대로 보내면 원치 않는 움직임
3. **잘못된 명령은 몸에 닿는다** — 화면 속 오류와 달리 로봇팔의 오류는 사람에게 닿음

## 4. 전체 흐름

```
[Python 서버]                         [Spring 서버]                       [화면]
 공개 뇌파 재생 (BCI IV 2a)             관문 (관제탑)                        관제 대시보드
 → CSP + LDA 판별          ──────→     ① 현재 참여 중인 환자인가?   ──────→  2D 로봇팔 1개
   왼손 상상 / 오른손 상상               ② 신호 품질이 정상인가?
   + 확신도 + 신호 품질                 ③ 확신도가 충분한가?
                                       ④ 오래된 명령이 아닌가?
 RAG (매뉴얼 + 오류 이력) ←────────     차단 시: 그 자리 정지 + 기록 → 조건 확인 후 수동 재개
```

### 목표 시연 흐름

> 명령 수신 → 관문 검사 → 팔 동작 → 오류 발생 → 정지·차단 기록 → RAG 점검 안내 → 조건 확인 후 수동 재개

## 5. 주요 설계 결정

| 항목 | 결정 |
|---|---|
| 로봇팔 | 1개. 왼손 상상 = 팔꿈치 굽히기, 오른손 상상 = 펴기 |
| 차단 시 | 원인과 상관없이 **그 자리에서 정지**, 자동 재개 없음, 서버가 상태를 다시 검사한 뒤 수동 재개 |
| 연결 끊김 | 워치독으로 감지. 짧은 끊김은 연속된 유효 데이터 확인 후 수동 재개, 오래 끊기면 초기화 필요 상태로 |
| 오래된 명령 | 실행하지 않고 지연·차단 사유를 기록 (기준 시간은 통신 실험 후 결정) |
| 참여 조건 | 연구 등록 기록이 있고, 지금 동의 중인 환자만 로봇팔 사용 가능 |
| 동의 철회 | 연구자 배정 삭제 + 로봇팔 사용 중단, 철회 시간·등록 기록은 유지 |
| RAG 권한 | 근거와 점검 방법 안내까지만. 팔 재개·상태 변경을 직접 실행하지 않음 |
| 정답 재생 시연 | 판별기가 준비되지 않으면 데이터셋 정답 라벨을 재생하되, 화면과 기록에 명시하고 성능 지표에서 제외 |

## 6. EEG 판별기 실험 원칙

- 공개 데이터 **BCI Competition IV 2a** (MOABB 이름: `BNCI2014_001`), 피험자 1명을 **결과를 보기 전에 무작위로 선택**
- 왼손·오른손 두 클래스, **CSP + LDA**
- **학습일 세션으로 학습**, **다른 날 세션으로 최종 평가 한 번**
- 설정 비교는 학습 데이터 안에서만 (평가 데이터를 보고 설정을 바꾸지 않음)
- 출력 지표: **정확도 + 카파 계수**
- 낮은 성능도 그대로 공개하고 원인을 분석. 한 사람의 결과를 다른 사람에게 일반화하지 않음

## 9. 진행 순서

```
0 개발 환경 구성                                    ✅ 완료
1 판별기: 피험자 무작위 선택 → 데이터 다운로드         ⏳ 다음
2 판별기: 왼손·오른손 선택, CSP + LDA 학습
3 판별기: 다른 날 데이터로 평가 → 정확도·카파
4 Python ↔ Spring 실시간 연결 + 통신 지연 실험
5 관제 대시보드 + 2D 로봇팔 + 차단 기록
6 RAG (매뉴얼 + 오류 이력)
7 Docker Compose → 발표
```

발표 이후: 역할별 화면(보호자·연구자·연구책임자 등), 로봇팔 → 사람 방향의 피드백(양방향 BCI의 뼈대), EEG-BIDS 형식 저장.
