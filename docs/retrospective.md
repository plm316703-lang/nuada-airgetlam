## 4. AI가 잘한 것

- **데이터 흐름을 따라 작은 단계로 나눔:** 재생기 → 관문 → DB → 화면 전송 → 화면 (B1-2a~B1-4)
- **화면이 아니라 서버에서 막는 설계:** 쉬운 정지 사유를 서버에서 변환(원문이 새지 않게), 비밀번호 변경 대기 계정은 증표 권한으로 서버가 차단
- **현업 방식 설명과 범위 나누기:** 관리자 발급·임시 비밀번호·실패 잠금·감사 기록·자동 로그아웃·초대를 R2~R4로 나눔
- **보안 세부:** 잠긴 동안 비밀번호를 아예 확인하지 않는 순서, 꾸밀 수 있는 IP 헤더를 믿지 않음, 초대 비밀값은 주소 `#` 뒤에 두고 해시만 저장
- **실제 상태를 직접 확인:** DB 칸 타입을 조회해 숨은 문제를 찾음(5장), 미리보기 페이지로 화면 그림을 확인

## 6. 내가 결정한 것 (사람의 역할)

- **방향:** 발표 프로젝트 → AI 활용 실험으로 전환, 기한 해제, 로그인을 "현업 방식 1~5, 7"까지 확대, 역할 UI를 B2보다 먼저
- **안전·개인정보 원칙 유지:** 환자·보호자에게 기술 문구를 보내지 않음, 보호자 초대에 신분 확인 필수, 가입 때 연구 동의를 받지 않음,
  관제 화면은 세션 중 자동 로그아웃 제외(경보를 놓치지 않게), 주입은 가짜 데이터만
- **숫자:** 5회·15분 잠금, 30분 자동 로그아웃, 임시 비밀번호 12자·72시간, 새 비밀번호 10자, 초대 72시간
- **검증:** 모든 단계를 직접 실행해 확인, 시간을 줄여 시험하는 방법으로 버그 발견
- 48개 결정 중 대부분은 Claude의 추천안을 골랐다. → 추천안을 고른 것도 결정이지만, **왜 그게 맞는지 내가 설명할 수 있는가**는 8장의 숙제로 남는다

## 7. 내 소감 (직접 쓴 말)

**놀랐던 점 / 좋았던 점**
> 이번 시험 특히나 Claude 에이전트로 대부분을 맡기면서 구현한 것들은 매우 놀랍고, 앞으로 에이전트가 없어서는 안 될 정도라고 느꼈다.
> 어디까지나 학습용으로 만든 프로젝트이지만, 실감하니 두렵기도 하다.
> 앞으로의 현업 방식과 코딩은 대부분 에이전트를 통해 이루어질 것 같다.

**아쉬웠던 점**
> 코드를 직접 안 보니 모르는 부분이 되어 버렸다. 마치 블랙박스처럼.
> AI도 현재 이런 수준이다. 이 부분에 대해서는 생각할 내용이 많다.

## 8. "블랙박스" 문제에 대한 생각 (Claude의 제안 — 내 결정 아님)

이번 실험에서 나는 **무엇을 만들지와 맞게 동작하는지**는 확인했지만, **어떻게 동작하는지**는 대부분 보지 않았다.
5장의 R3 버그처럼, 동작 확인만으로도 잡히는 문제가 있지만 코드를 모르면 "왜 그런지"를 스스로 찾을 수 없다.
아래는 이 간격을 줄이는 방법 제안이다.

1. **설명 점검:** 기능마다 "이 부분이 왜 이렇게 됐나" 질문 2~3개를 받아 내 말로 답해 본다 (막히는 곳 = 공부할 곳)
2. **테스트를 입구로 읽기:** 자동 테스트 17개는 "이 코드가 무엇을 보장하나"를 짧게 적은 문서다. 코드 전체보다 테스트부터 읽는다
3. **한 부분은 직접 쓰기:** RAG를 LangChain으로 다시 구현하는 것처럼, 정답(지금 코드)이 있는 부분을 내가 직접 짜고 AI는 리뷰만 한다
4. **진행 방식 조절:** 다음 프로젝트에서는 "중요한 파일 하나는 코드를 보여 달라"처럼 블랙박스로 둘 부분과 열어 볼 부분을 미리 정한다
