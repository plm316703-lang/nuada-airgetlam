# STALE_COMMAND — 오래된 명령 (지연)

> Nuada Airgetlám 점검 매뉴얼 (연구용 프로토타입, 의료기기 매뉴얼 아님). 로봇팔 재개는 관제 화면의 수동 재개로만 한다.

## 증상
- 관문 판단 기록에 STALE_COMMAND(오래된 명령)가 나타나고 로봇팔이 정지된다.
- 판별기가 만든 시각과 관문이 받은 시각의 차이가 기준(2초)을 넘었다.

## 원인
- 네트워크 지연, 판별기 PC 과부하로 메시지가 늦게 도착.
- 판별기 PC와 관제 서버 PC의 시계가 서로 다름.
- 메시지에 시간대(+09:00)가 빠지거나 잘못 들어감.

## 확인 방법
1. 판단 기록의 상세(age=…ms)로 얼마나 늦었는지 확인한다.
2. 두 PC의 시계를 비교한다 (인터넷 시간 동기화 사용 여부).
3. 판별기 PC의 CPU 사용량을 확인한다.

## 해결 단계
1. 시계가 다르면 두 PC 모두 시간 동기화를 켠다.
2. 과부하면 판별기 PC의 다른 프로그램을 종료한다.
3. 정상 지연으로 돌아오고 연속 정상 데이터가 쌓이면 관제 담당자가 수동 재개를 요청한다.
4. 늦게 온 명령은 다시 보내거나 대신 실행하지 않는다 (그 사이 상황이 바뀌었을 수 있음).

## 안 될 때
- 지연이 계속되면 통신 지연 실험 결과를 보고 기준값을 연구책임자와 다시 정한다. 기준값을 임의로 늘리지 않는다.
